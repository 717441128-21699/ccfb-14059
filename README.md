# 航站楼广播自适应噪声补偿处理器

网页版广播处理器:监听麦克风实时估计大厅环境噪声,广播播出时按各频段噪声
高出参考值的量逐频段抬升语音增益,短促冲击噪声(行李车撞击)与持续嘈杂
分开对待,输出声压级有上限。

- DSP 写在 **AudioWorklet** 里(`src/worklet/`),核心算法是纯 TypeScript、
  不依赖 Web Audio(`src/dsp/`),因此同一套代码既跑在音频线程,也能在
  Node 里做自动化验证
- 配置与界面用 **TypeScript**(`src/ui/`),含扬声器分区配置、实时处理监视、
  增益曲线、播出记录四块
- 大厅噪声与广播语音由 `src/sim/synth.ts` 合成(人声嘈杂、行李车撞击、
  夜间空调、伪语音),也可切换真实麦克风

## 运行

```bash
npm install
npm run build
npm start          # → http://localhost:8080
```

打开页面后点 **▶ 启动**,选择场景(早高峰大厅 / 半夜空厅 / 行李车冲击 /
突发噪声 +20dB / 客流渐强),点 **📢 播放广播** 触发广播。

## 架构

```
src/dsp/        纯 TS 的 DSP 核心(Node 可测)
  Biquad.ts           二阶滤波器(分析/语音滤波器组)
  NoiseCompensator.ts 单分区补偿器:噪声估计 → 冲击识别 → 增益映射 → 限幅
  MultiZoneEngine.ts  8 分区引擎
  types.ts            分区配置 / 全局动态参数 / 统计类型
src/worklet/    AudioWorklet 处理器(音频线程,加载 DSP 核心)
src/sim/        场景合成(嘈杂人声、撞击、夜间 HVAC、伪语音)
src/ui/         界面(app / panels / main)
test/verify.ts  需求验证(npm test)
server.mjs      极简静态服务器
```

## 关键设计

**冲击 vs 持续噪声。** 宽带电平突然跳变(>8dB)即进入评估期,噪声估计与
增益先冻结:评估期内电平从峰值跌落 8dB 以上 → 判为冲击(行李车撞击),
记录事件并继续冻结 1s;电平在峰值 4dB 以内持续 120ms → 判为持续噪声,
立即放行快速跟随。冲击按"快速衰减的瞬态"识别——持续 0.1s 以上不衰减的
矩形突发在物理上不属于撞击声,会被当作短暂噪声处理。

**快慢双分量增益。** 增益 = 0.91 × 快分量(τ=25ms)+ 0.09 × 慢分量
(τ=1.5s)。快分量保证 20dB 阶跃在 300ms 内跟上约 90%;慢分量把"完全跟
上"拖到持续 2 秒以上的噪声才达到,避免增益被中短时波动顶满。

**声压级上限。** 两层:增益映射时按宽带语音电平截断(语音电平 + 增益
≤ maxSplDb),输出端再做整块 RMS 硬限幅兜底。

**实时性。** 所有缓冲预分配,process() 内零分配(统计对象就地更新),
8 分区 × 128 采样每块约 0.08ms,远低于 3ms 预算。

## 已知简化(正式部署需替换)

- 分析/合成滤波器组为二阶带通,非完美重构;正式系统应用 Linkwitz-Riley
  分频或 FFT 滤波器组
- 演示语音为共振峰合成的伪语音,正式接入 TTS / 寻呼话筒音源即可
- 电平约定 0 dBFS ≈ 94 dB SPL,实际系统需按话筒灵敏度与功放增益标定
- 浏览器只能监听一路输出,界面监听当前选中分区;8 分区全部实时处理并计量
